Server admin

Provisioning, hardening and maintaining Linux servers in production — with access controlled per person and patching held to a schedule rather than to convenience.

LinuxUbuntu ServerNginxSSHsystemdBash

The situation

Servers are commonly stood up once and then left alone until something breaks. Credentials are shared, patches lag by months, and nobody can say with confidence who still has access to what.

How I approach it

I treat administration as a standing discipline rather than an installation event. Access is provisioned per person and revoked on exit, patching runs to a planned window, and every routine task is documented well enough to hand over.

In practice

What the work covers.

Scope of work

  • Linux server provisioning, hardening and baseline configuration
  • User account lifecycle, role-based permissions and privilege review
  • Scheduled patching planned around operational hours
  • Service configuration, web servers, databases and reverse proxies
  • Resource monitoring and capacity planning
  • Runbook documentation so routine work does not depend on one individual

What it delivers

  • Access that ends when employment does
  • Patch posture measured in days rather than quarters
  • Servers that can be rebuilt from documentation, not memory
  • Capacity understood before it becomes a constraint
